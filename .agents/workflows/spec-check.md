# /spec-check — 착수 전 지시서 대조

지시서·명세는 리뷰어가 쓴다. 리뷰어도 틀린다(LESSONS 2026-11-23: 출결 함수 지목, KST 문자열 시간대).
**코드를 실제로 만지는 너는 그 코드의 주인이다.** 시작하기 전에 지시서를 코드에 대 보고, 어긋나면 고치지 말고 먼저 보고한다.

1. 이번 티켓에서 지시서가 가리키는 기존 이름(함수, 파일, 테이블, 열, RPC, 설정 키)을 전부 적는다.
2. 이름마다 정의를 찾고 결과를 붙인다.
   ```bash
   grep -rn "<이름>" src supabase/migrations
   ```
   - 없음 → 멈추고 보고.
   - 있음 → 매개변수를 읽는다. 지시서대로 부르면 빠지는 인자가 있으면(예: 투표·지각 기준) 멈추고 보고.
   - 같은 일을 하는 더 위의 함수가 있으면(예: `buildMemberScheduleRecords`) 그것을 쓰자고 제안한다.
3. 변환하는 데이터(날짜·시간·숫자 text 열)는 그 값을 **쓰는 쪽 코드**를 찾아 형식을 확인한다(예: `fn_get_kst_now_string()` → 시간대 없는 KST). 지시서의 가정과 다르면 멈추고 보고.
4. 지시서의 테스트 예시를 읽고, 빠진 틀리기 쉬운 경우를 1~3개 덧붙인다(사유 있는 불참, 병합 회원, 오늘 아직 시작 안 한 일정, 빈 저장소, 데이터 늦게 도착, 390px).
5. 결과를 PR 댓글이나 보고서 맨 앞에 "착수 확인" 표로 남긴다.

| 이름 | 정의 위치 | 지시서와 일치 | 메모 |
|---|---|---|---|

어긋난 항목이 하나라도 있으면 그 티켓은 시작하지 않고 보고한다. 다른 독립 티켓은 진행해도 된다.
