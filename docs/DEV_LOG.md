## 2026-10-14: Phase 1 — MVP 코어 구축 & 5대 도메인 불변식 확립

### 1. 배경 및 기획 의도
- 합창단 현장에서 매주 카카오톡 투표와 종이 출석부로 출결을 관리하면서 출석 통계 집계 공수가 크고 대리 출석 위험이 존재함.
- 앱 설치 없이 모바일 브라우저에서 QR 1초 스캔 또는 현장 PIN으로 출석하고, 백엔드는 총무진이 가장 다루기 쉬운 구글 스프레드시트와 실시간 연동하는 웹앱 기획.

### 2. 주요 개발 내용
- **도메인 모델 수립 (`src/types/rollbook.ts`)**: 단원 명부(`Member`), 일정(`Schedule`), 사전투표(`RSVP`), 원천로그(`RawAttendanceLog`).
- **하네스 헌법 제정 (`AGENTS.md`)**:
  - 원천 로그 분리 (Append-Only Event Sourcing): 출결 로그는 절대 덮어쓰거나 임의 삭제하지 않음.
  - 모바일 터치 타깃 최소 44px 이상 유지.
  - 결정론적 테스트 통과(Green Bar: `typecheck`, `lint`, `test`) 필수.
- **모바일 QR 스캐너 (`src/components/QRScannerModal.tsx`)**: `jsQR` 기반 웹캠 실시간 스캔.
- **하버사인 거리 계산 (`src/utils/geo.ts`)**: 브라우저 GPS 위경도를 기반으로 연습실 반경(기본 100m) 검증.

### 3. 발생했던 문제 & 트러블슈팅
- **문제 1**: 모바일 사파리/크롬에서 카메라 권한 요청 시 HTTPS 미지원 환경에서 WebRTC 비디오 스트림 차단 오류 발생.
  - **원인**: 브라우저 보안 정책상 `getUserMedia`는 `localhost` 또는 `https://`에서만 허용됨.
  - **해결**: 개발 환경에 Vite HTTPS 플러그인 구성 및 GitHub Pages 배포를 통해 정식 SSL 인증서 적용.
- **문제 2**: 구글 시트 API 호출 시 CORS 에러 발생.
  - **원인**: Google Apps Script(GAS) Web App은 기본적으로 `POST` 요청에 대해 302 리다이렉트를 반환하며, 브라우저 `fetch` 시 CORS 헤더 누락 시 차단됨.
  - **해결**: `mode: 'no-cors'` 또는 JSONP 형태의 안전한 GAS 어댑터 통신 패턴 구축.

## 2026-10-15: Phase 2 — 전문 어드민 센터 & 반복 캘린더 엔진

### 1. 배경 및 기획 의도
- 매주 일정을 하나씩 수동으로 등록하는 것이 번거로우므로, 네이버/애플 캘린더 스타일로 [매주 특정 요일 N주간 반복] 일괄 생성 지원.
- 매주 새로운 QR을 인쇄할 필요 없이 연습실 벽면에 1년 내내 붙여둘 수 있는 **상설 마스터 QR** 및 현장 PIN 발급 체계 구축.
- 토스(Toss) 스타일의 깔끔한 카드형 단원별 출결 통계 및 필터링 대시보드 구축.

### 2. 주요 개발 내용
- **반복 전개 유틸 (`src/utils/calendar.ts`)**: `expandRecurringSchedules` 함수로 N회차 날짜 자동 계산 및 개별 일정 생성.
- **상설 마스터 QR & 커스텀 인쇄**: 네이버 QR 스타일의 안내문구 편집 프레임 및 인쇄 최적화 CSS.
- **단원 인적사항 모달 (`MemberProfileModal.tsx`)**: 개인 연락처(전체 번호 입력, 뒤 4자리 본인 인증), 상태(정단원/준단원/휴단원/퇴단원/선생님/객원) 관리.

### 3. 발생했던 문제 & 트러블슈팅
- **문제 1**: 단원 관리에서 인적사항 클릭 시 흰 화면(White Screen / React Crash) 발생.
  - **원인**: `formData.phoneLast4`가 `undefined`인 레코드에서 `.slice(-4)`를 호출하여 런타임 널 포인터 에러 발생.
  - **해결**: 안전한 기본값 어댑터 `String(formData.phone || formData.phoneLast4 || '').replace(/\D/g, '')` 적용으로 과거 레코드 방어.
- **문제 2**: 수정 중 실수로 바깥을 클릭했을 때 작성 내용이 즉시 날아가는 문제.
  - **원인**: 모달 오버레이 클릭 시 무조건 `onClose()` 호출.
  - **해결**: `isDirty` 상태 추적을 통해 변경 사항이 있을 경우 "변경사항을 저장하지 않고 종료하시겠습니까?" 컨펌 팝업 출력.

## 2026-10-16: Phase 2.5 — 네이버 지도 기반 위치 픽커 & 구글 시트 장소정보 동기화

### 1. 배경 및 기획 의도
- 관리자가 위도/경도 숫자를 직접 알기 어려우므로, **네이버 지도 및 도로명 주소 검색**으로 연습실을 등록하고 출석 인정 반경(50m~500m)을 원으로 시각화하여 설정할 수 있어야 함.
- 저장된 연습실/공연장 정보(`LocationPreset`)가 로컬스토리지에만 저장되어 다른 기기나 관리자와 공유되지 못하는 문제를 해결하기 위해, 구글 시트 5번째 탭(`장소정보`)을 신설하여 양방향 동기화.
- 잘못 대량 생성된 정기 일정을 한꺼번에 삭제하거나 수정할 수 있는 일괄 관리 체계 요구.

### 2. 주요 개발 내용
- **네이버 지도 픽커 (`LocationPickerMap.tsx`)**:
  - Daum/카카오 도로명 주소 우편번호 API 연동 (별도 API 키 필요 없음).
  - 네이버 지오코딩 및 인터랙티브 지도 원형 오버레이(Circle Overlay)로 출석 인정 반경 조절.
  - 도로명 주소 + 상세 주소(층/호수) + 입구 위치 안내(오시는 길) 입력 필드 분리.
- **구글 시트 5대 탭 체계 확립 (`google-apps-script.js`)**:
  - `SHEET_NAMES.LOCATIONS = '장소정보'` 추가.
  - `SAVE_LOCATION`, `DELETE_LOCATION` 액션 핸들러 구현.
  - `BATCH_DELETE_SCHEDULES` (하단 행부터 역순 삭제 알고리즘으로 행 인덱스 밀림 버그 방지).
  - `BATCH_UPDATE_SCHEDULES` (지정된 복수 일정 일괄 속성 업데이트).
- **일괄 관리 UI 구축**:
  - `ScheduleEditModal.tsx`: 단일 일정 수정/삭제 및 "동일 명칭 전체 회차 일괄 적용/삭제" 지원.
  - `BatchScheduleEditModal.tsx`: 체크박스로 선택한 N개 일정에 대해 장소/시간/카테고리/설명 선택적 일괄 업데이트.
  - `AdminDashboard.tsx`: `📅 캘린더 날짜별 보기` vs `📋 전체 등록 일정 일괄 관리` 탭 분리.

### 3. 발생했던 문제 & 트러블슈팅
- **문제 1**: 장소 삭제 시 팝업이 닫히며 삭제가 취소되거나 오작동하는 현상.
  - **원인**: 삭제 버튼 클릭 이벤트가 모달 배경 오버레이로 버블링(`e.stopPropagation()` 누락)되어 모달 닫힘과 삭제 컨펌이 충돌.
  - **해결**: `e.stopPropagation()` 명시 및 삭제 로직 분리.
- **문제 2**: 구글 시트에서 복수 일정 일괄 삭제 시 엉뚱한 행이 삭제되는 문제.
  - **원인**: 위에서부터 행을 지우면 아래 행들의 행 번호(Row Index)가 하나씩 당겨져서 후속 행 번호가 어긋남.
  - **해결**: 삭제 대상 행 번호를 내림차순(Bottom-to-Top)으로 정렬하여 아래에서부터 위로 지우는 결정론적 알고리즘 적용.
- **문제 3**: 신규 단원을 추가해도 새로고침하면 사라지는 문제.
  - **원인**: 초기 로드 시 `fetchRemoteData()`로 구글 시트 데이터를 가져올 때 로컬 추가분이 덮어씌워지거나 시트 저장 호출이 누락됨.
  - **해결**: `addMember` 서비스에서 즉시 로컬 캐시를 갱신하고 구글 시트에 `ADD_MEMBER`를 전송하도록 동기화 보강.

## 2026-10-17: Phase 3 — 정기 일정 3단 제어, 시즌 복제, 인라인 UX & QR 매칭 안정화

### 1. 배경 및 기획 의도
- **기타(직접 입력) UX 단절**: 파트, 카테고리에서 '직접 입력'을 고르면 입력창이 뜨지 않고, 장소는 새 장소 픽커로 바로 이어지지 않는 문제.
- **QR 매칭 불안감**: 상설 QR과 당일 회차별 QR 중 무엇을 찍어도 지금 어떤 연습으로 출석 처리되는지 스캐너 화면에서 실시간으로 알 수 없어 불안함.
- **정기 일정 제어 한계**:
  - 학기 중간(예: 11월)에 연습실이 바뀌었을 때 과거 9~10월 출결은 보존하고 앞으로 남은 일정만 일괄 변경하는 "이 일정 및 향후 모든 일정" 기능 부재.
  - 매 학기 반복되는 16주 일정을 원클릭으로 다음 학기로 복제하는 기능 요구.
- **데이터 고아화(Orphan) 방지**:
  - `seriesId`를 도입하더라도 출결 원천로그(`logs`)와 사전투표(`RSVP`)는 반드시 개별 `scheduleId`만을 바라보아야 하며, 단일 일정 수정 시 `scheduleId`를 바꾸지 않고 In-place 갱신하여 기존 출결 데이터의 영구 보존 보장.

### 2. 주요 개발 내용
- **`LocationPickerModal.tsx` 신설 및 원스톱 장소 등록**:
  - 인라인 지도 컴포넌트인 `LocationPickerMap`을 모달 팝업으로 감싸, 일정 등록/수정 모달(`ScheduleEditModal`) 및 어드민 대시보드(`AdminDashboard`) 어디서든 버튼 하나로 도로명 검색 및 반경 설정을 마치고 즉시 해당 일정의 장소로 자동 선택되도록 연결.
- **인라인 '직접 입력' 지원**:
  - `MemberProfileModal`: 파트 드롭다운에서 `✏️ 기타 (직접 입력)...` 선택 시 인라인 input 필드 노출 및 커스텀 파트 실시간 반영.
  - `ScheduleEditModal` & `AdminDashboard`: 카테고리 드롭다운에서 `+ 새 구분 직접 추가` 인라인 input 제공.
- **스캐너 상단 실시간 일정 매칭 배지 (`QRScannerModal.tsx`)**:
  - 스캐너 상단에 `[🎯 오늘 연습 출석: 2026-10-17 정기연습 | 제1연습실 (19:30~22:00)]` 실시간 시각화.
  - "벽면 상설 QR 또는 회차별 QR 중 아무거나 스캔해도 위 일정으로 정상 출석됩니다" 직관적 안내문 추가.
- **`seriesId` 기반 구글 캘린더 스타일 3단 수정/삭제 (`ScheduleEditModal.tsx`)**:
  - 수정 시: `[이 일정만 변경]` (In-place) / `[이 일정 및 향후 모든 일정 일괄 변경]` (과거 출결 보존, 오늘 이후 미래 회차만 반영) / `[전체 N개 회차 모두 일괄 변경]`
  - 삭제 시: `[이 회차만 삭제]` / `[⏩ 향후 N회차 삭제]` / `[전체 일괄 삭제]`
- **시즌 일정 템플릿 복제 (`duplicateScheduleSeries`) & 아카이빙**:
  - 특정 시리즈 일정을 새 학기 시작일에 맞춰 일괄 복제하며, 신규 `scheduleId`, 신규 `seriesId`, 새 출석 PIN을 발급하여 과거 출결/투표 데이터 격리 보장.
  - `📁 지난 시즌 아카이브 열람 / 📂 지난 시즌 숨기기` 토글 지원.
- **구글 시트 헤더 기반 동적 매핑 (`google-apps-script.js`)**:
  - 고정 9열 대신 1행 헤더 키(`headers.map`) 기반으로 동적 매핑하여 `seriesId`, `seriesIndex`, `seriesTotal` 하위 호환성 확보.

- `reconcileMemberAttendance(memberId, scheduleId)` 메서드 신설:
  - 마이페이지, 단원 프로필 팝업, 홈 화면의 출결 판정을 관리자 화면과 완전히 동일한 중앙 엔진으로 일원화.
  - **최신 관리자 액션 우선 채택 (Recency Resolution)**: 동일 일정에 여러 개의 로그가 쌓였을 때, 최신 로그(`findLast`)를 최종 상태로 판정하여 관리자 수동 인정이 즉시 반영되도록 보장.
  - `isExempt` 플래그 연동: 입단일 이전 일정이거나 휴단/퇴단 기간일 경우 결석이 아닌 '모수제외'로 명확히 표기.

#### ⑤ 단원 전용 마이페이지(MemberPortalModal) 2탭 구조 전면 개편
- 사용자 요구사항을 100% 수용하여 2개 탭으로 단순화:
  - **탭 1 (출결 & 투표 로그 표)**: `[연습명칭 / 연습일 / 투표 상태 / 출결 시간]` 4열 대조 테이블.

### 5. 도메인 불변식 교훈
- **단일 진실 공급원(SSOT)의 엄격성**:
  - 출결 판정(`reconcileAttendance`)과 같은 비즈니스 핵심 로직은 절대로 UI 컴포넌트마다 각자 `filter`나 조건문으로 중복 구현해서는 안 된다. 화면이 달라도 같은 엔진을 호출해야 데이터 불일치 민원을 원천 차단할 수 있다.
- **Append-only와 Recency Resolution의 결합**:
  - 이벤트 소싱(원천 로그 불변) 환경에서는 과거의 실수를 고칠 때 로그를 삭제/수정하는 것이 아니라 새 이벤트를 뒤에 덧붙인다. 따라서 뷰 투영(Projection) 시점에는 최신 타임스탬프의 이벤트가 이전 상태를 덮어쓰도록 결정론적 정렬을 보장해야 한다.
- **데이터 파이프라인의 자가 치유(Self-healing) 설계**:
  - 시트의 과거 레코드에 `0000`이나 빈 값이 있더라도, 사용자가 앱을 이용하는 자연스러운 과정(로그인 등)에서 정상 데이터로 스스로 갱신되도록 설계하면 수동 DB 작업 비용을 획기적으로 줄일 수 있다.
