# 12. 네이티브 앱 전환 검토 및 외부 카메라 QR 딥링크·알림 구조 분석 (ADR)

> **작성일**: 2026-11-08  
> **상태**: 검토 완료 및 현상 유지 결정 (네이티브 앱 전환 단계에서 재검토)  
> **관련 논의**: 외부 카메라 QR 직행 출석, PWA 브라우저 저장소 격리, 1인 1기기 인증 락, 푸시 알림

---

## 1. 검토 배경 및 요구사항

### 1.1 사용자의 요구사항
1. **스마트폰 기본 카메라로 벽면 QR을 촬영했을 때**:
   - 웹앱으로 즉시 연결.
   - 이미 기기 인증(바인딩)된 상태라면 당일 출석 체크로 자동 직행.
   - 미인증 상태라면 단원 선택(또는 신규 가입) 후 당일 출석으로 연속 처리.
2. **카카오톡 인앱 브라우저 차단**:
   - 카톡 인앱 브라우저로 열릴 경우 동작을 중단하고 외부 브라우저(Safari / Chrome)로 튕기거나 안내 팝업 노출.
3. **객원 단원 패스트트랙**:
   - 전화번호 전체 인증 대신 현장 PIN 4자리로 가볍게 출석 인정.
4. **개인별 기기 1회 제한 락(`boundDeviceId`) 복원 희망**.

---

## 2. 기술적 분석 및 구조적 한계 (PWA vs Native)

### 2.1 결정적인 충돌: [기존 단원의 PWA 설치] vs [기본 카메라 촬영] vs [1인 1기기 락]
- **현실**: 합창단 단원들은 이미 홈 화면에 **문콰이어 웹앱(PWA)**을 설치해 본인 인증을 완료한 상태임.
- **모바일 OS 웹 기술의 한계**:
  - 스마트폰 기본 카메라(iOS/Android)로 웹 URL QR을 스캔하면, 이미 설치된 PWA가 열리는 것이 아니라 **Safari 또는 Chrome의 새 브라우저 탭**이 열림.
  - **WebKit 스토리지 파티셔닝**: iOS Safari와 홈 화면 PWA는 `localStorage`와 쿠키가 엄격히 격리되어 있음.
  - 사파리 탭은 PWA 앱의 인증 정보를 공유받지 못하므로 **미인증 상태**로 열림.
- **충돌 결과**:
  - 이 상태에서 "1인 1기기 락"을 엄격하게 복원하면, 사파리에서 단원이 본인 이름을 선택하는 순간 **"이미 다른 기기(문콰이어 PWA 앱)에 연동된 계정입니다"** 에러가 발생하며 출석이 차단됨.

### 2.2 카카오톡 인앱 브라우저의 한계
- 카카오톡 내부 브라우저에서 인증할 경우 카톡 내부 저장소에만 프로필이 갇히며, PWA 설치가 불가능함.
- iOS에서는 스크립트로 Safari를 강제 자동 실행할 수 없으므로, 차단 오버레이 안내창을 띄우는 것이 최선임.

### 2.3 웹 푸시 알림의 제약
- 현재 Google Sheets + 정적 호스팅(GitHub Pages) 구조에서는 단원 개개인에게 "연습 3일 전 투표 독려", "연습 1시간 전 장소 공지"와 같은 푸시 알림을 안정적으로 보내기 어려움.
- iOS는 PWA 홈 화면 추가 + OS 16.4 이상에서만 웹 푸시를 지원하여 일반 단원들에게 진입 장벽이 높음.

## 3. 의사결정 (Decision)

> **"현재 단계에서는 현상(PWA 내부 스캐너 + 무마찰 재연동)을 유지하고, 추후 푸시 알림 및 외부 카메라 딥링크가 필수적인 시점에 진짜 네이티브 앱(Flutter / React Native)으로 전환한다."**

### 결정 근거:
1. **MVP 검증 충실**:
   - 현재 구글 시트 기반 웹앱은 합창단 출결 규칙, 생애주기, 모수 계산 로직을 안정적으로 검증하는 데 최적화되어 있음.
   - 억지로 모바일 브라우저 한계를 우회하려다 단원들의 현장 출석 실패(기기 락 사고)를 유발할 위험이 큼.
2. **현행 방식의 안정성**:
   - 단원들은 이미 설치된 문콰이어 PWA 앱을 켜서 **앱 내 [출석하기(스캐너)]**로 벽면 QR을 촬영하고 있으며, 이 방식이 기기 락과 저장소 분리 문제 없이 가장 안전함.

## 4. 추후 네이티브 앱(React Native / Flutter) 전환 시 해결되는 항목들

향후 정식 모바일 앱으로 패키징/전환 시 아래 기능들이 완벽하게 구현 가능함:

| 기능 | 웹앱(PWA) 현 상태 | 네이티브 앱 전환 시 |
| :--- | :--- | :--- |
| **기본 카메라 스캔 시 앱 직행** | 불가 (무조건 Safari/Chrome 브라우저로 열림) | **Universal Links / App Links**로 설치된 앱이 0.1초 만에 실행되며 즉시 출석 |
| **푸시 알림 (Push Notification)** | 매우 제한적 (iOS 복잡한 권한, 백그라운드 한계) | **FCM 기반 백그라운드 푸시 알림** (투표 리마인더, 연습 안내 등) |
| **1인 1기기 본인 인증** | `localStorage` 격리로 브라우저마다 충돌 | **하드웨어 고유 식별자 / Face ID / 지문 인증**으로 대리 출석 원천 차단 |
| **카톡/외부 브라우저 파편화** | 카톡 인앱 브라우저로 인한 저장소 격리 발생 | 앱 스토어 설치 기반이므로 브라우저 파편화 문제 영구 해소 |
| **오프라인 / 지하 연습실 출석** | 네트워크 불안정 시 초기 로딩 실패 가능 | 로컬 캐시 + 네이티브 저장소로 지하 연습실에서도 즉시 스캔 후 나중에 동기화 |
