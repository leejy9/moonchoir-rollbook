# 배포 절차 (Runbook)

> 마지막 갱신: 2026-10-22. 2026-10-21~22에 겪은 배포 사고를 반복하지 않기 위한 기록입니다. 결정과 근거는 [구조 복구 기록](ARCHITECTURE_RECOVERY.md), 작업 이력은 [DEV_LOG](DEV_LOG.md), 작업 목록은 [tasks.md](tasks.md)를 봅니다.

## 구조 한눈에
| 대상 | 위치 | 배포 방법 |
|---|---|---|
| 화면(프런트엔드) | GitHub Pages (`gh-pages` 브랜치) | 로컬 터미널에서 `npm run deploy` |
| 서버 | Apps Script 웹 앱 (구글 시트에 연결) | 편집기에 코드를 붙여넣고 **새 버전**으로 배포 |

- **두 가지는 따로 배포됩니다.** 서버를 먼저, 화면을 나중에 올립니다. 새 서버는 옛 화면과 호환되지만, 새 화면이 옛 서버를 만나면 새 기능이 오류를 낼 수 있습니다.
- **`npm run deploy`는 커밋이 아니라 로컬 폴더에 저장된 파일 그대로 빌드해서 올립니다.** 커밋·푸시하지 않은 변경도, 오래된 `main`도 그대로 라이브에 올라갑니다.

## 1. 서버(Apps Script) 배포
1. 저장소의 `google-apps-script.js` 전체를 복사합니다(`docs/google_apps_script.js`는 같은 내용의 사본이며 두 파일은 항상 일치해야 합니다).
2. 구글 시트 → 확장 프로그램 → Apps Script에서 **기존 코드를 전부 지우고 붙여넣은 뒤 저장**합니다. 저장 후 구문 오류(예: `Unexpected end of input`)가 없어야 합니다. 있으면 코드가 중간에 잘려 붙은 것이므로 전체를 다시 복사합니다.
3. **배포 → 배포 관리 → 연필(편집) → 버전: 새 버전 → 배포.** **`새 배포`를 만들면 웹 앱 주소가 바뀌어** 앱과 단원 기기에 저장된 주소가 모두 맞지 않게 됩니다.
4. 시트 탭을 **새로고침(F5)** 하면 상단 `🎵 문콰이어 출석부` 메뉴가 갱신됩니다(메뉴는 시트를 열 때 만들어집니다). 안 보이면 편집기에서 `onOpen`을 한 번 실행합니다.
5. 메뉴의 `전화번호 텍스트 서식 동작 확인`을 실행해 두 줄이 모두 `✅ 보존`인지 확인합니다. 이 기능은 임시 탭을 만들었다가 그 탭만 지우며 기존 탭은 건드리지 않습니다.
6. 편집기 위쪽 함수 선택칸에서 `setMemberPhoneCellsAsText` 같은 도우미 함수를 직접 실행하지 않습니다(값을 받아야 동작하므로 `Cannot read properties of undefined` 오류가 나는 것이 정상입니다).
7. 메뉴의 `기존 기록 날짜/시간을 한국 표준시(KST)로 변환`은 출석 로그의 시간 칸을 제자리에서 덮어쓰는 기능이라 평소에 실행하지 않습니다(표시용 KST 변환은 앱에서 처리합니다).

## 2. 화면(프런트엔드) 배포
```bash
cd /Users/grasshop/Desktop/Antigravity/Moonchoir_rollbook
git status                 # 아무것도 안 나와야 함. 수정된 파일이 있으면 pull 하지 말고 먼저 정리
git switch main
git pull origin main       # 빠뜨리면 옛 코드가 배포됩니다
npm ci
npm run deploy
```
- 카카오 지도 키(`VITE_KAKAO_MAP_API_KEY`)는 로컬 `.env`에 있고 저장소에는 없습니다. `.env`가 없거나 비어 있으면 코드의 기본 키로 빌드되므로, 평소 배포하던 컴퓨터에서 배포합니다.
- 배포 후 1~2분 뒤 사이트를 새로고침해 **화면 왼쪽 아래에 `방금 동기화됨`** 알약이 보이면 새 화면이 올라간 것입니다. 옛 화면이 보이면 브라우저 새로고침을 한 번 더 합니다.
- 커밋하지 않은 로컬 작업은 배포 전에 별도 브랜치에 커밋해 보존합니다(`git switch -c 브랜치이름` → `git add -A` → `git commit` → `git push -u origin 브랜치이름`).

## 3. 배포 후 점검표
1. 화면 왼쪽 아래 `방금 동기화됨`이 보이는지
2. 마이페이지 → `개인 대시보드` 탭 맨 위에 `📲 앱처럼 설치하기` 카드가 보이는지(설치된 앱 안에서는 숨김)
3. 카카오톡 인앱 브라우저에서 연동한 뒤 일반 브라우저에서도 같은 이름·전체 전화번호로 연동되는지
4. 출석 후 시트 `출석원천로그`의 `deviceId` 열에 값이 기록되는지
5. 관리자 매트릭스에서 투표한 칸이 `참석 · 투표`처럼 보이는지
6. 주소 검색에서 핀이 잡히는지(안 되면 화면에 뜨는 안내 문구를 확인)
7. 새 단원 추가 후 전화번호 뒷 4자리의 앞자리 0이 유지되는지

## 5. 카카오 지도 키 관리
- 코드의 기본 키는 `src/utils/kakaoMaps.ts`의 `KAKAO_APP_KEY`이며, 로컬 `.env`의 `VITE_KAKAO_MAP_API_KEY`가 있으면 그 값이 우선합니다. 배포본에 어떤 키가 들어갔는지는 배포 사이트의 `sdk.js` 요청(Network 탭)에서 `appkey=`로 확인합니다.
- JavaScript 키는 **카카오 개발자 콘솔의 앱마다 따로** 있고, 도메인 등록(`JS SDK 도메인`)과 `카카오맵` 사용 설정도 **앱마다 따로**입니다. 다른 앱에서 키를 새로 받아 바꾸면 그 앱에 이 사이트(`https://leejy9.github.io`, 경로·끝 슬래시 없음)를 등록하고 카카오맵을 켜야 합니다(2026-10-20 `b561…`로 교체한 뒤 403이 났던 사고).
- **로컬 `.env`의 `VITE_KAKAO_MAP_API_KEY`는 코드의 기본값보다 우선하고, 배포할 때 코드에 박혀 들어갑니다.** 코드의 기본 키를 바꿔도 `.env`에 옛 키가 있으면 효과가 없습니다(2026-10-22 사고). 키를 바꿀 때는 `grep KAKAO .env`로 확인하고 `.env`를 고친 뒤 **반드시 다시 배포**합니다.
- 앱의 `카카오맵` 사용 설정(제품 설정)이 꺼져 있으면 키·도메인이 맞아도 `sdk.js`가 거절됩니다. 켠 뒤에는 장소 설정 창에 `도로명주소 좌표 변환 연결됨`(초록)이 표시됩니다.
- 키 검증은 라이브 사이트의 Network 탭에서 `sdk.js`의 Status를 봅니다(`200` 정상, `403`·`401` 카카오 거절). 주소창에 `sdk.js` 주소를 직접 열면 사이트 주소(Referer)가 안 붙어 도메인 제한 키는 정상이어도 거절되므로 검증에 쓰지 않습니다.
